# ⚠️ Phase 22G: Dataset Generalization Risk Audit Report

This document records the empirical investigation into dataset structure, template artifacts, intra-class similarity, and generalization risks for **Resume Intel**'s training dataset ([`clean_mapped_resumes.csv`](file:///c:/Users/pinak/Desktop/RESUME_SCREENIG/ml/data/processed/clean_mapped_resumes.csv), 1,848 records).

---

## 🔍 Empirical Investigation Findings

### 1. Template Contact Header Artifact ("Jessica Claire")
- **Empirical Observation**:
  - Scanning the leading 50 characters across all 1,848 cleaned resumes revealed that **687 out of 1,238 resumes sourced from `resumes.csv` (55.5%)** contain an identical synthetic placeholder header:
    `"Jessica Claire 100 Montgomery St, San Francisco, CA..."`
- **Root Cause**:
  - The public Kaggle `resumes.csv` dataset was generated by anonymizing original candidate names/addresses with a single standardized placeholder template (`Jessica Claire`).
- **Generalization Risk**:
  - Because this header appears across multiple categories in `resumes.csv` (but not in `resumes_dataset.jsonl`), linear classifiers could learn minor sub-correlations with source-specific formatting rather than domain-pure technical skills.

## 🛡️ Identified Model Promotion Blockers & Risks

1. **Cloud Computing Sample Size Limit (92 total samples)**:
   - While Candidate Model v2 achieved 100% recall on the 14 Cloud Computing test set resumes, the total pool of 92 Cloud resumes has a higher mean intra-class similarity (0.6152). Out-of-distribution cloud resumes (e.g. specialized GCP/OpenStack enterprise architects) could experience lower real-world accuracy.
2. **Contact Header Preprocessing Need**:
   - Future data cleaning pipelines should strip standardized contact block headers (`Jessica Claire...`) prior to TF-IDF vectorization to ensure feature weights remain 100% focused on professional experience and technical skills.
